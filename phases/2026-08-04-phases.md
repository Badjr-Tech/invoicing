## Phase 0 — Done (as of this date)

  ownership checks on every API route, upload lockdown, real password reset
- 7-day trial → gate; locked members browse everything, writes blocked
- Onboarding: 6-step tour, hub, payments step (UI only), meeting step
- Fee module: 7/5/3 flat bands, boundary floor, ACH vs card, integer cents — 37 tests
- Design system: sage/ember/clay, Manrope + DM Sans, ~100 pages rethemed,
  landing page, split auth screens, branded HTML email template (Brevo)
- Bird's Eye View dashboard; financials dashboard rebuilt
- DB migration applied (trial/onboarding/Stripe columns)

## Phase 1 — Stripe Connect onboarding 🔴 blocked on sk_test_ key

Express accounts, `controller.fees.payer = 'application'` (irreversible,
load-bearing). Store account id immediately on creation. Account Links flow
with return/refresh. `account.updated` webhook flips `stripe_charges_enabled`.
Payments step goes from placeholder to real. Invoice sending stays gated on
charges being enabled.

## Phase 2 — Webhook subsystem

`stripe_events` table, signature verification, persist-before-process with
unique event id (idempotency), async processing, out-of-order tolerance.
Tests: duplicate delivery, replay, malformed signature, unknown type, event
for deleted business.

## Phase 3 — Payment collection on invoices

Pay button + hosted payment page per invoice. Direct charges on the connected
account, `application_fee_amount` from the fee module (fee base excludes
`fee_exempt` lines). ACH default; expected-arrival copy. `revenue_snapshots`
nightly + `agency_fee_records` per charge.

## Phase 4 — Automatic bookkeeping

On payment: income row (gross) + AGENCY fee expense row. On payout: transfer
row — never income (the double-count bug). Property test: no event sequence
double-counts revenue. Payout detail view ("invoiced $500 → fee $35 → $465").

## Phase 5 — ACH returns

Late failures reverse income + fee + fee record together via `reversed_by_id`;
invoice back to unpaid. Tests.

## Phase 6 — Card toggle

Off by default. Enable flow with the rate-change confirm (§4.3). Fee reads the
method off the actual charge, not the setting.

## Phase 7 — Member email setup

Screen where a member picks the local part (name@agencydomain) + reply-to;
stored on the business; all member-to-client mail (invoices, contracts) sends
as that address via Brevo. Plumbing already supports per-send sender/reply-to.

## Phase 8 — Scopes & payment links

SOW generator (Scope of Work 101, mandatory hours cap). Standalone payment
links for non-invoice collection. Both attach to clients; links collect
through Connect like invoices.

## Phase 9 — Admin money surface

Revenue dashboard: fees by period/member/band/method, growth + quiet-member
signals, approaching-band-change list. Request queue generalized (one typed
queue). Resource library with visibility rules.

## Phase 10 — Onboarding meeting diagnostic

Six-Month Audit as structured fields (stage, entity, revenue sources, fixed vs
variable, owner pay, reserves, gaps, next step, readiness flags). Configures
the member's platform and feeds Phase 11.

## Phase 11 — Service funnel + managed engagement

Products get `visibility_rule` (min trailing revenue + diagnosis flags).
DJC services surface when readiness triggers — member readiness, not our
capacity. Managed-engagement offer above a threshold (Dakotah's tier —
threshold/pricing/stacking still open).

## Phase 12 — Launch hygiene

Rotate the live Stripe key (standing item). Vercel env parity. `useFormState`
→ `useActionState` sweep + the 118 legacy type errors. Terms: data-visibility
language, referral fee, monthly minimum decisions. 1099-K confirmation with an
accountant before first January.
